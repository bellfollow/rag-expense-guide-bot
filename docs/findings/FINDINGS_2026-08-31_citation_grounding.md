# FINDINGS — citation 근거 없이 판정만 맞았다

날짜: 2026-08-31
대상: 영수증 r001/r002/r004 (지원불가 3건), `/classify-receipt` 컴플라이언스 검색 쿼리

**한 줄**: 지표는 이미 천장이었는데, 판정 근거는 18/18 전부 틀린 조항이었다.

---

## 1. 발단

status/flag 불일치(compliance_status가 flag=지원불가인데 확인불가로 강등되던 문제)를 고치던 중,
macro recall은 이미 100%였다. 게이트 수정 후 compliance_status가 위반의심으로 정상화된 것을
확인하는 김에 citation을 눈으로 열어봤다가, r001(유류비)·r004(주차비)의 인용문이
유류비·주차비와 무관한 조항이라는 걸 발견했다.

## 2. 실측 — 수정 전 18/18 전부 틀린 조항

r001/r002/r004 × 6회(이전 세션들에서 쌓인 jsonl 재사용, 재호출 없이 파싱) = 18건 전수 확인.
L248(유류비)/L258(주차비) 인용 0건. 대신 매번 "참고 2. 창업탐색비 불인정 기준 - 공통사항 2.
연구개발과제 수행과 관련이 없거나 증명서류가 미비한 집행 금액"이라는 무관 조항을 인용했다.

결론은 맞고 근거는 틀린 상태였다 — 분류 단계(taxonomy)가 이미 정답(flag=지원불가)을 냈고,
컴플라이언스는 override_flag=지원불가로 동의만 했을 뿐, citation은 실제 근거가 아니었다.

## 3. 헛짚음 — curl 인코딩 버그를 인덱싱 문제로 오진

bash curl로 `/search`에 한국어 쿼리를 GET 파라미터로 보냈는데, Windows 환경 인코딩 문제로
서버에 도달한 문자열이 깨져 있었다(`repr()` 찍어보니 `'ȸ�Ǻ�...'`). 그 상태로 여러 쿼리를
찔러보고 "검색 결과가 항상 비슷한 걸 보니 인덱싱 자체에 문제가 있는 것 아닌가"하는 가설을
세웠다. Python `requests`로 바꿔 쏘니 정상 동작 — 도구 결함을 시스템 결함으로 오진한 것이었다.
**진단 도구부터 의심해야 한다.**

## 4. item 쿼리 시도 → 측정으로 기각

extract 단계 출력인 `item`(예: "휘발유 구입")을 검색어에 더해보는 방안을 먼저 시도했다.
`/search`로 guiideline.pdf chunk 8(유류비/렌터카/주차비 조항이 실제로 들어있는 청크) 순위를
직접 비교했다:

| 쿼리 | chunk8 순위 | 점수 |
|---|---|---|
| 휘발유 구입 | 미포함 | - |
| 주차 요금 | 3위 | 0.2165 |
| 휘발유 구입 여비 | 1위 | 0.2861 |
| 주차 요금 여비 | 1위 | 0.3527 |
| 유류비 | 3위 | 0.2810 |
| 주차비 | 3위 | 0.2780 |
| 유류비 지원되지 않으며 | 미포함 | - |
| 주차비 일비 포함 별도 청구 불가 | 1위 | 0.3032 |
| **국내여비 유류비 렌터카 주차비 청구 불가** | **1위** | **0.4273** ← 채택 |

`item` 단독으로는 chunk8을 못 끌어오거나(미포함) 순위가 낮다(0.22~0.35). 실제로 붙였던
`f"{item} 불인정 기준"` 접미사는 "참고 2. 창업탐색비 불인정 기준"이라는 표 제목과 리터럴로
겹쳐서 매번 그 표 쪽으로 새어나갔다 — item의 의미 신호보다 "불인정 기준" 문자열 매치가 더
강하게 작용했다.

## 5. 채택 — 고정 쿼리 2개

taxonomy의 금지 목록이 유한·고정이므로 쿼리도 고정으로 충분하다는 결론으로, item 쿼리를
롤백하고 고정 쿼리 2개로 교체했다:

```python
queries = [
    "국내여비 유류비 렌터카 주차비 청구 불가",
    "회의비 현물성 물품 구매 지급 불가 불인정기준",
]
```

## 6. 결과

r001/r002/r004 단독 3회 + 31장 3회 재검증: citation 정답 조항 인용 9/9(3회), 3회 동일 패턴,
교차오염 0건(r004가 유류비 조항을 물어오지 않았고, r001/r002가 주차비 조항을 물어오지
않았다 — 고정 쿼리 2개를 매번 같이 던지는데도 영수증마다 자기 사유에 맞는 조항만 인용됐다).
회귀 없음: macro recall 100%(3회), status 최솟값 97%, 금액 94%, 날짜 97~100%,
is_receipt 오탐 0.

## 7. 남은 구멍

범용기자재(PC/노트북)·귀금속 조항은 이 고정 쿼리로 커버 안 된다(국내여비 조항만 겨냥) —
해당 영수증이 평가셋에 0건이라 쿼리가 그 조항을 끌어오는지 검증 자체가 불가능하다.
