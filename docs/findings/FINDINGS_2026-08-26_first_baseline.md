날짜: 2026-08-26
입력: 영수증 31장 (`labels_prefilled.csv`), `/classify-receipt` HTTP
결과: 30/31 성공 (r030은 Gemini 429 quota 초과)

---

## 1. 한 줄 요약

**시스템이 판정을 거꾸로 하고 있다.**
애매한 식비는 자신있게 거절하고, 지침에 명시적으로 금지된 유류비·주차비는 판단을 미룬다.

30장 안 돌렸으면 "데모 잘 되는데?"로 끝났을 결과다.

## 2. 측정값 — 세 종류로 갈린다

| 지표 | 값 | 분류 |
|---|---|---|
| 날짜 | 29/30 (97%) | ✅ 진짜 |
| 금액 | 24/30 (80%) | ⚠ **하한선** — 라벨 오류 포함 |
| 비목 분류 | 17/30 (57%) | ✅ 진짜 |
| flag | **1/30 (3%)** | ✅ **진짜. 핵심 문제** |
| compliance status | 0/30 (0%) | ❌ **측정 버그** |
| 과신율 | 26/27 (96%) | ✅ 진짜 (단 방향이 예상과 반대) |

### ❌ status 0% = 측정 버그였음

```python
# 러너가 읽던 것
d["compliance"].get("status")            → 항상 None

# 파이프라인 실제 (config.py L175)
{"compliance_status": "준수|위반의심|확인불가", ...}
```

필드명(`status` vs `compliance_status`)도 다르고, 값 어휘(`ok/review/violation` vs `준수/위반의심/확인불가`)도 달랐다.
러너에 필드명 수정 + `STATUS_MAP` 매핑 추가. **재측정 전까지 status는 미지수다.**

### ⚠ 금액 80%는 하한선

오류 6건 중 최소 3건은 **라벨 쪽이 틀렸다.**

| id | 라벨 | 모델 | 판정 |
|---|---|---|---|
| r019 | 71,950 | 11,950 | 모델이 맞음 — `1`→`7` OCR 오독 |
| r006 | 73,700 | 13,700 | 모델이 맞음 — 같은 패턴 |
| r017 | 70,720 | 23,900 | 라벨 의심 |
| r028 | 1,200 | 12,000 | 라벨 의심 (×1.1 추정치였음) |

전부 라벨링 때 "최대값 근거 / 사진 확인 필요"로 표시했던 13건 안에 있다.
`1↔7` 오독은 EasyOCR의 대표 실패 패턴이며, 실제 금액 정확도는 80%보다 높다.

## 3. 핵심 발견 — 판정 방향 역전

```
애매한 식비 26건    →  지원불가 / 해당없음     (자신있게 거절)
명백한 지원불가 3건  →  확인필요               (판단 유보)
```

### 3-1. 과잉 거절 (26/30)

식당·카페·편의점 영수증 대부분을 `flag=지원불가`, `sub_item=해당없음`으로 판정.

추정 원인 — **미검증 가설**:
`RECEIPT_CATEGORY_TAXONOMY`(config.py L121-123)의 주의사항이 너무 강하게 작동한다.

> "사업 관련 회의비 및 현물성 물품 구매는 지급하지 아니한다" — 회의 목적 식비/다과/물품은 지원 불가.

식당 영수증에는 회의 여부를 알 수 있는 정보가 없다. 모델이 안전한 쪽(거절)으로 기운 것으로 보인다.
분류 프롬프트 Rule 2가 "지원불가면 해당없음으로, 억지로 끼워맞추지 마라"를 강조하는 것도 이 방향을 강화했을 수 있다.

### 3-2. 명백한 위반을 놓침 (3/3 전부)

| id | 파일 | 실제 | 모델 |
|---|---|---|---|
| r001 | 성수주유소 85,000원 | 지원불가 (L248) | 확인필요 |
| r002 | 풍차주유소 70,428원 | 지원불가 (L248) | 확인필요 |
| r004 | 고양터미널 주차 13,500원 | 지원불가 (L258) | 확인필요 |

추정 원인 — **미검증 가설**:
분류 단계는 RAG 없이 `RECEIPT_CATEGORY_TAXONOMY`만 본다(pipeline.py 주석: "목록이 작고 완결돼있어 검색보다 안정적").
그런데 taxonomy에는 `국내여비(운임/숙박비/식비/일비)`만 있고 **다음 두 금지 조항이 없다**:

- L248: "자가 이용 시 동일구간 내 대중교통비 정액을 기준으로 집행한다. **유류비는 지원되지 않으며**, 이 때 톨비 영수증을 제출하여야 한다."
- L258: "출장지 내에서 소요되는 교통비(버스, 지하철, 택시 요금 등), **주차비 등의 각종 비용은 일비에 포함되므로 별도로 청구할 수 없다.**"

주유소·주차장 영수증은 taxonomy만 보면 `국내여비(운임)`처럼 보인다.

**둘 다 가설이다.** 확정하려면 `classification.reasoning`을 봐야 하는데 1차 러너가 저장하지 않았다(러너 결함, 수정 완료).

## 4. 이번에 드러난 러너 결함 2개

1. **필드명 미확인** — `compliance.status`가 존재하지 않는 필드였다. 러너를 짜기 전에 `config.py`의 출력 스키마를 확인했어야 했다.
2. **판정 근거 미저장** — `reasoning` / `compliance_notes` / `citation`을 버렸다. 그래서 §3의 원인이 전부 가설로 남았다.

둘 다 수정 완료(`run_eval.py`). 재실행 시 `rec["raw"]`에 근거가 저장된다.

## 6. 평가셋 구성 기록 (재현용)

- 원본 영수증 105장 → `raw_text` 중복 제거 → **100장**
- 선별 **31장**, 기준은 2×2(결제수단 × 인정가능) 균형 + 조항 커버리지

| 태그 | 수 |
|---|---|
| 출장중식비 (익산 클러스터 7/13~15, 8/24~25) | 8 |
| 일상식비 (구로 60장 중 8장만 — majority baseline 억제) | 8 |
| 다인분 회의비후보 (품목 8개↑) | 4 |
| 지원불가 확정 (주유2 + 주차1) | 3 |
| 현물성물품 후보 (편의점) | 3 |
| 출장중 카페 / 구로 카페 | 2 + 2 |
| 숙박 상한초과 (익산 모텔 520,000원) | 1 |

**남은 구멍**: 31장 전부 롯데법인카드다. `개인카드 × 인정가능` 칸이 비어 있어
결제수단이 정답과 상관될 위험이 남아 있다. 다이소 재료비·서점 문헌구입비 등
개인카드 결제 3~4장을 나중에 끼워넣어야 한다.
