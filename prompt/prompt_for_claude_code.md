# 지시: 영수증 분류 프롬프트 수정 (과잉 거절 해소)

## 배경 — 측정 결과

평가셋 31장으로 측정했다. `flag` 정확도가 **0/31**이었고, 원인이 두 방향이다.

**(A) 과잉 거절 — 26건**
정답이 `확인필요`인 28건 중 **28건 전부**를 단정했다. 대부분 `지원불가`로.
분류 근거의 논리 패턴이 일관되게 이렇다:

```
"출장 명령이나 여비 정산 내역 등의 증빙이 없어 → 회의 목적 식비로 간주 → 지원 불가"
"출장 중 식사로 볼 수 있는 명확한 근거가 없으므로 → 지원불가로 판단"
"회의 목적인지 명시되지 않았으나 → 일반적인 소액 식음료는 회의비로 간주"
```

**"증빙이 없다"를 "확인필요"가 아니라 "회의비로 간주"로 처리**하고 있다.
정보 부족을 불리한 추정으로 메꾸는 것이다. 그러면서 `confidence`는 전부 `high`였다.

**(B) 명시적 금지를 놓침 — 3건**
주유비 2건(가이드라인 "유류비는 지원되지 않으며"), 주차비 1건("주차비 등은 일비에 포함되므로
별도로 청구할 수 없다")을 전부 `확인필요`로 통과시켰다.

이번 수정은 **(A)만 다룬다.** (B)는 분류 단계가 RAG를 쓰지 않아 생기는 별개 문제이고,
(A)를 고친 뒤 남는 오차를 보고 따로 판단한다.

## 현재 Rule (문제 지점)

```
2. flag가 "지원불가"인 경우: main_category와 sub_item을 모두 "해당없음"으로 표기하라. (…)
3. flag가 "정상" 또는 "확인필요"인 경우에만 main_category는 (…) sub_item은 위 목록의
   세부항목명 중 하나를 그대로 사용하라.
4. 지원 불가 항목(회의비 등)에 해당하면 flag를 "지원불가"로, 비목은 맞으나 증빙/한도 등이
   애매하면 "확인필요"로, 명확히 지원 가능하면 "정상"으로 표기하라.
5. confidence는 판단 확신도(high/medium/low).
```

**결함 2개:**

1. Rule 4가 "지원 불가 항목에 **해당하면**"이라고만 하고 **해당 여부의 판정 기준이 없다.**
   그래서 "회의비일 수도 있다"가 "해당한다"로 흐른다.

2. Rule 2/3이 `확인필요`일 때 `sub_item`을 taxonomy 중 하나로 **강제**한다.
   그런데 "비목 자체를 특정할 수 없어서 확인이 필요한" 경우가 실제로 존재한다
   (사무실 근처 식당 영수증 — 출장 식비도 아니고 회의비라 단정할 수도 없음).
   지금은 그 조합이 표현 불가능해서, 모델이 `지원불가 + 해당없음`으로 도피한다.

## 넣을 Rule (아래 텍스트 그대로)

Rule 2~5를 아래로 교체한다.

```
2. flag가 "지원불가"인 경우: main_category와 sub_item을 모두 "해당없음"으로 표기하라.
   목록에 있는 비목명에 억지로 끼워맞추지 마라(예: 회의 목적 식비를 "창업탐색추진비"나
   "국내여비(식비)"로 분류하지 말 것 — 그 항목들은 다른 목적의 지출을 위한 것이지
   회의비의 대체 명칭이 아니다).

3. flag가 "정상"인 경우: main_category는 "시제품제작비"/"활동비"/"기타 사업운영 경비"
   중 하나, sub_item은 위 목록의 세부항목명 중 하나를 그대로 사용하라.
   flag가 "확인필요"인 경우: 비목이 특정되면 위와 같이 표기하고, 영수증 정보만으로는
   어느 비목인지 특정할 수 없으면 main_category와 sub_item을 "해당없음"으로 두어라.
   비목을 특정할 수 없다는 것 자체가 확인이 필요한 사유다.

4. flag 판정 기준 — 아래 순서로 적용한다.
   4-1. "지원불가"는 영수증에 실제로 인쇄된 사실만으로 금지 조항에 걸릴 때만 쓴다.
        (예: 상품명이 주류·귀금속류, 결제일이 협약기간 밖, 품목이 명백한 범용성 기자재)
        영수증에 없는 정황을 추정해서 "지원불가"로 판정하지 마라.
   4-2. 판단 근거에 다음 표현이 들어간다면 그것은 "지원불가"가 아니라 "확인필요"다:
        "~로 추정된다", "~로 간주된다", "~로 보인다", "~일 가능성이 높다",
        "증빙이 없으므로", "목적이 명시되지 않았으므로", "불명확하므로"
        증빙이 없다는 것은 지급 불가의 근거가 아니라 확인이 필요하다는 근거다.
   4-3. 식당·카페·편의점 영수증에는 그 지출이 회의 목적이었는지 여부가 인쇄되지 않는다.
        따라서 회의비 금지 조항만을 근거로 "지원불가"를 판정할 수 없다.
        "확인필요"로 하고, reasoning에 무엇을 확인해야 하는지(회의 목적 여부, 출장 여부,
        참석자 등) 구체적으로 적어라.
   4-4. "정상"은 영수증 정보만으로 비목과 집행 적정성이 모두 확인될 때만 쓴다.
   4-5. 위 어디에도 확신이 없으면 "확인필요"가 기본값이다.

5. confidence는 판단 확신도(high/medium/low).
   reasoning에 4-2의 추정 표현이 하나라도 들어갔다면 "high"를 쓰지 마라.
```

## 검증

**[1] 회귀 측정** — 같은 31장으로 재측정한다.

```
python run_eval_v2.py --api http://localhost:5000 --labels <labels_prefilled_1.csv>
```

수정 전 대비 아래 방향으로 움직여야 한다.

| 지표 | 수정 전 | 기대 |
|---|---|---|
| flag | 0/31 | **크게 상승** (정답 28건이 `확인필요`) |
| 과신율 | 28/28 (100%) | **크게 하락** |
| 비목 분류 | 18/31 | 유지 또는 상승 |
| 금액 / 날짜 | 29/31, 30/31 | **변동 없어야 함** (추출 단계 미변경) |

**[2] 악화 감시 — 이게 더 중요하다.**

`확인필요`를 남발하게 만드는 수정이면 실패다. 아래를 반드시 확인하라:

- **놓친 지원불가**가 3건보다 **늘어나면 안 된다.**
  주유(r001, r002)·주차(r004)는 원래 (B) 문제라 이번 수정으로 해결되지 않지만,
  **악화되어서도 안 된다.**
- 모든 건이 `확인필요`로 수렴하면 그것은 개선이 아니다.
  `정상`과 `지원불가`가 각각 최소 1건 이상 나오는지 확인하라.

**[3] 금액·날짜가 변했다면 멈춰라.** 추출 단계를 건드리지 않았는데 변했다면
의도치 않은 부작용이므로 원인을 먼저 밝혀라.
