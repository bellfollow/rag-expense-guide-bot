# 지시: 분류 단계에 금지 조항 목록 제공 (수정 E)

## 배경 — 분산의 원인을 국소화했다

같은 이미지를 3번씩 태워 단계별 출력의 **동일성**(정확도가 아니라)을 비교했다.

### 결정적 증거 — `20260803_133500.jpg` (성수주유소)

```
① 추출  vendor    "성수주유소"      1값 ✅
① 추출  item      "휘발유 주유"     1값 ✅
① 추출  amount    85000            1값 ✅
① 추출  date      "2026-08-03"     1값 ✅
        ↓ 입력이 글자 하나 다르지 않다
② 분류  flag      "확인필요" / "지원불가"   🚨 갈림
② 분류  confidence "low"            1값 (모델도 자기가 모른다는 걸 안다)
```

**입력이 완전히 동일한데 분류 결과가 갈린다.** 분류 단계 자체가 흔들린다는 직접 증거다.

### 왜 흔들리는가 — 판단 근거가 없다

주유비가 지원 불가라는 근거는 가이드라인에만 있다.

> L248 — "자가 이용 시 동일구간 내 대중교통비 정액을 기준으로 집행한다.
> **유류비는 지원되지 않으며**, 이 때 톨비 영수증을 제출하여야 한다."

그런데 분류 단계는 RAG를 쓰지 않고 `RECEIPT_CATEGORY_TAXONOMY`만 본다.
거기에는 이 조항이 **없다**. 모델은 답을 모르니 비슷한 확률의 후보
(`해당없음` / `국내여비(운임)` / `소모품비`) 사이에서 매번 다르게 찍는다.

`confidence`가 `low`로 고정된 것이 이를 뒷받침한다.

**흔들림은 LLM의 결함이 아니라 정보 부족의 증상이다.** `temperature=0`으로 막을 수 없다.

### 이미 있는 규칙이 죽어 있다

수정 A에서 넣은 Rule 4-1은 이렇다.

```
4-1. "지원불가"는 영수증에 실제로 인쇄된 사실만으로 금지 조항에 걸릴 때만 쓴다.
```

**참조할 금지 조항 목록이 taxonomy에 없어서 실행 불가능한 규칙이었다.**
이번 수정은 그 목록을 제공해 4-1을 되살리는 것이다.

---

## 수정 대상

`config.py` 의 `RECEIPT_CATEGORY_TAXONOMY` — **"주의사항(지원 불가 항목):" 블록만** 교체한다.

건드리지 마라:
- 비목 목록(1. 시제품제작비 / 2. 활동비 / 3. 기타 사업운영 경비) 본문
- `GEMINI_RECEIPT_CLASSIFY_MODEL`의 Rule 0~5 (4-1이 이 목록을 참조하게 되므로 그대로 둔다)
- `GEMINI_RECEIPT_COMPLIANCE_MODEL`, `GEMINI_RECEIPT_EXTRACT_MODEL`
- `PROHIBITION_MARKERS`, override 게이트, `pipeline.py` 전체

**분류 단계에 RAG를 붙이지 마라.** 지금 고치려는 것이 불안정성인데,
검색을 추가하면 불안정 요인이 하나 더 생긴다. 텍스트로만 해결한다.

## 현재 블록

```
주의사항(지원 불가 항목):
- "사업 관련 회의비 및 현물성 물품 구매는 지급하지 아니한다" — 회의 목적 식비/다과/물품은 지원 불가.
  단, 국내여비 세부항목인 "식비"(출장 중 식사)는 지원 가능 — 회의 중 식사인지 출장 중 식사인지 구분 안 되면 확신을 낮추고 확인 필요 사유를 명시할 것.
```

## 넣을 블록 (아래 텍스트 그대로)

```
주의사항 — 지침에 명시된 지원 불가 항목:

아래는 가이드라인 원문에 단정적 금지 표현으로 적힌 항목이다.
영수증에 인쇄된 사실만으로 아래에 해당함이 확인되면 flag를 "지원불가"로 판정하라.
추정이 필요하면 "확인필요"다(Rule 4-2 참조).

[영수증만으로 판정 가능한 금지 항목]
- 유류비(주유소 결제, 휘발유·경유 구입): "유류비는 지원되지 않으며" — 지원불가.
  자가용 이용 시에는 동일구간 대중교통비 정액으로만 집행하며, 톨비 영수증만 인정된다.
  주유소 영수증은 그 자체로 지원 불가이며 출장 목적 여부를 확인할 필요가 없다.
- 주차비(주차장 결제): "출장지 내에서 소요되는 교통비(버스, 지하철, 택시 요금 등),
  주차비 등의 각종 비용은 일비에 포함되므로 별도로 청구할 수 없다" — 지원불가.
- 렌터카 이용료: "국내 출장 시 렌트카 이용 경비는 청구할 수 없다" — 지원불가.
- 출장지 내 택시·버스·지하철 요금: 위와 같은 조항으로 일비에 포함 — 지원불가.
  (출장지까지의 이동 운임인 KTX·시외버스 승차권은 국내여비(운임)로 지원 가능하다.)
- 범용성 기자재(PC, 노트북, 태블릿)와 범용 소프트웨어(한글, MS-Office 등): 구매 금지 — 지원불가.
- 귀금속·보석 등 쥬얼리 재료: "원칙적으로 구매가 불가능" — 지원불가.

[영수증만으로는 판정할 수 없는 금지 항목 — "확인필요"로 둘 것]
- "사업 관련 회의비 및 현물성 물품 구매는 지급하지 아니한다" — 회의 목적 식비/다과/물품은
  지원 불가이나, 영수증에는 그 지출이 회의 목적이었는지가 인쇄되지 않는다.
  식당·카페·편의점 영수증을 이 조항만으로 "지원불가"로 판정하지 마라.
  국내여비 세부항목인 "식비"(출장 중 식사)는 지원 가능하므로, 회의 중 식사인지
  출장 중 식사인지 구분되지 않으면 "확인필요"로 하고 확인이 필요한 사유를 명시하라.
- 협약기간 밖 집행, 과제와 무관한 지출, 친족 간 거래: 영수증만으로 확인 불가 — "확인필요".
```

목록을 임의로 늘리지 마라. 위 항목은 모두 가이드라인 원문에 근거가 있고,
**영수증 이미지만으로 판정 가능한지 여부로 두 그룹으로 나눈 것**이다.
이 구분이 이번 수정의 핵심이다.

## 검증

측정은 내가 직접 돌린다. 평가셋은 이 레포에 없다. **약식 검증을 하지 마라.**

이번에는 **정확도보다 재현성**이 먼저다.

| 항목 | 현재 | 성공 조건 |
|---|---|---|
| 주유·주차 3장의 `flag` 고유값 (3회 반복) | 2 (흔들림) | **1 (고정)** |
| 31장 macro recall 3회 범위 | 48~82% (34%p) | **범위 15%p 이하** |
| 지원불가 recall | 0~2/3 | **3/3 안정** |
| 확인필요 recall | 96~100% | **93% 이상 유지** |
| flag 출력 종류 | 2 | 2 이상 유지 |
| 금액·날짜 | 94%, 97% | **변동 없음** |

**분산 축소가 이번 수정의 목표다.** 평균이 조금 올라도 범위가 그대로면 실패다.

가장 큰 위험은 **과잉 거절 재발**이다. 금지 항목 목록이 길어지면 모델이
다시 모든 것을 `지원불가`로 밀 수 있다(수정 A 이전 상태).
`확인필요 recall`이 93% 아래로 떨어지면 되돌린다.

## 하지 말 것

- 분류 단계에 RAG를 붙이지 마라
- 분류 프롬프트 Rule 0~5를 수정하지 마라 (Rule 4-1이 이 목록을 참조한다)
- 추출 프롬프트를 건드리지 마라 (금액·날짜가 안정적이므로 위험만 크다)
- 금지 항목을 임의로 추가하지 마라 — 가이드라인 원문에 근거가 없으면 넣지 마라
- 비목 목록(15개 세부항목) 자체를 수정하지 마라
- 커밋하지 마라
