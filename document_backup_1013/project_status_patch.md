### 이번 세션 작업 — 평가셋 구축과 판정 정확도

**영수증 31장 평가셋을 만들고, 처음으로 시스템에 숫자를 붙였다.**

| 지표 | 이전 | 현재 |
|---|---|---|
| **macro recall (flag)** | **0%** | **100%** (3회 반복, 분산 0%p) |
| 지원불가 recall | 0/3 | 3/3 |
| 확인필요 recall | 0/28 | 28/28 |
| 과신율 | 100% | 0% |
| 금액 / 날짜 추출 | — | 94% / 97% |
| `compliance_status` | — | 90% (다수결 베이스라인과 동일, 순이득 0) |
| 비목 분류 | — | 65~71% |

측정에서 드러난 것 두 가지:

1. **판정이 거꾸로였다.** 애매한 식비는 `지원불가`로 단정하고,
   지침에 명시적으로 금지된 유류비·주차비는 `확인필요`로 유보했다.
2. **1회 측정으로는 개선을 판정할 수 없었다.** 동일 코드 3회 실행에서
   macro recall이 48~82%로 흔들렸고, 그 34%p 안에서 네 번의 수정을
   "개선/악화"로 잘못 판정했다.

원인은 LLM 비결정성이 아니라 **분류 단계에 판단 근거가 없었던 것**이다.
금지 조항을 "영수증만으로 판정 가능한가"로 갈라 taxonomy에 제공하자
정확도와 재현성이 동시에 해결됐다.

상세: `document/FINDINGS_2026-08-26_first_baseline.md`,
`document/FINDINGS_2026-08-28_variance.md`
